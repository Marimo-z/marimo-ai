# 开发记录

## 2026-10-14 · 阶段 0 + 阶段 1

### 环境

- Windows 11（2880×1800，200% 缩放），Node 24.19，npm 11.17，npm 源为 npmmirror。
- 仓库初始只有 `AI_DEVELOPMENT_SPEC.md` 和 `logo.svg`，没有可复用的代码。

### 完成内容

- 工程骨架：electron-vite 5 + Vue 3 + TS 6 + Pinia + Vitest + ESLint/Prettier。
- 透明、无边框、置顶、不显示任务栏按钮的桌宠窗口；单实例锁。
- CSS/SVG 机器人：沿用 logo 的蓝色圆球和胶囊眼，加入径向渐变、高光和地面阴影。
- 6 种表情（平静/好奇/开心/生气/难过/思考），以及说话、拖动两种动作状态；随机眨眼。
- 全局光标追踪 + 眼睛平滑偏移；拖动与单击/双击区分；点击挤压回弹反馈。
- 说话气泡：逐字显示、自动换行、最大高度滚动、点击展开、× 关闭、悬停暂停收起、按文本长度决定停留时间。
- 原生右键菜单与托盘菜单；鼠标穿透模式；窗口位置记忆与多显示器可见性修正。
- 普通配置持久化（zod 按字段容错、原子写入、兼容 BOM）。

### 验证结果（实际执行）

- `npm test`：8 个测试文件，43 个用例全部通过。
- `npm run typecheck`、`npm run lint`、`npm run build`：通过。
- `npm run dev` 实机运行，通过注入鼠标事件并截图验证：透明背景、眼睛追踪、单击出气泡并切换表情、拖动（无误触发单击，位置写入 `config.json`）、右键原生菜单。
- CPU（本机 Electron 报告 `gpu_compositing: disabled_software`，即纯软件渲染）：
  - 60fps CSS 浮动动画：静止时约占单核 50%，**不合格**；
  - 关闭浮动：约 1.6%；
  - 改为 15fps 定时器驱动：约 23%；再加 `will-change`：约 14%；
  - 最终 10fps + `will-change`：约占单核 8%（16 核机器总占用约 0.5%）。
  - 在 GPU 合成可用的机器上，这部分开销应明显更低。

### 假设与决策

- **形象以 `logo.svg` 为准**（蓝色 `#4f68b0` 圆球 + 白色胶囊眼）。规格书里写的"白色外壳 + 深色面板 + 青色眼睛"与 logo 不一致，且规格书引用的 `/logo.png` 实际上不存在。
- 双击目前只提示"控制面板建造中"，阶段 2 改为打开控制面板。
- 右键菜单、托盘里未实现的入口（聊天、小游戏、设置、控制面板）显示为禁用的"（即将推出）"。
- 鼠标穿透模式下隐藏气泡，因为此时气泡无法被关闭。

### 已知问题

- Electron 44 不再通过 postinstall 下载二进制，而是在首次运行时下载；国内网络需先设置 `ELECTRON_MIRROR`（见 README）。
- npm 11 的 install-script 白名单会提示 esbuild 的 postinstall 未执行；已验证 esbuild 可以正常工作，可忽略。
- 点击桌宠会让桌宠窗口获得焦点（从当前应用夺走焦点）。阶段 3 需要在桌宠窗口内输入时再决定是否改为 `focusable: false`。
- 待机浮动在软件渲染下仍有约 8% 单核占用；可通过托盘关闭"待机动画"。后续可考虑在长时间无交互时自动降频。
- 自动化测试只覆盖纯函数；窗口行为依赖手动验收。
- 尚未在多显示器或不同 DPI 组合的环境下实测，只有单元测试覆盖可见性修正逻辑。

## 2026-10-14 · 阶段 2：控制面板与配置

### 完成内容

- 初始化 Git 仓库，推送到 `https://github.com/Marimo-z/marimo-ai.git`（`.gitignore` 排除 `node_modules`、构建产物、`.env*`、`secrets.json`、日志和编辑器配置；配置与密钥实际保存在 `%APPDATA%\marimo`，本就不在仓库中）。
- 控制面板窗口：单例、隐藏标题栏 + 系统按钮覆盖层、侧栏导航、6 个页面（总览、AI 配置、人设与记忆、语音设置、桌宠设置、游戏中心）。
- `SettingsService`：分区读取 / 更新 / 恢复默认；更新严格校验，读取按字段容错；桌宠、面板、托盘菜单共用这一个入口。
- `SecureStorage`：API Key 经 `safeStorage`（DPAPI）加密，单独存入 `secrets.json`；渲染进程只能查询状态，不能读回明文。
- AI 连接测试：主进程请求 OpenAI 兼容的 `/models` 端点；强制 HTTPS（本机除外），错误分类，不泄露密钥和响应内容。
- 服务商预设：DeepSeek、通义千问（兼容模式）、OpenAI、Ollama（本地，不需要密钥）、自定义。
- 新增桌宠设置：缩放 0.6–1.6、互动灵敏度、气泡停留时间、免打扰、双击行为、开机启动（仅打包版本生效）。
- 双击桌宠打开面板；再次启动程序时显示桌宠并打开面板；右键菜单"小游戏"和"设置"跳转到对应页面。
- 主题：系统 / 浅色（蓝白）/ 深色（深蓝黑），原生菜单与标题栏按钮同步。

### 验证结果（实际执行）

- `npm test`：11 个测试文件，64 个用例全部通过（新增设置服务、连接测试、纯数据克隆的测试）。
- `npm run lint`、`npm run build`（包含两套类型检查）：通过。
- 实机运行：通过第二次启动程序打开面板，深色主题显示正常。
- 用一个临时 Electron 脚本在隐藏窗口中加载开发服务器上的面板，逐页截图（6 个页面 × 浅色 / 深色），并收集控制台输出。截图发现除总览外的页面都是空白，控制台显示 `DataCloneError`：`structuredClone` 不能克隆 Vue 的响应式 Proxy。改用 `plainClone`（JSON 往返）并补充测试后，12 张截图全部正常、控制台无报错。
- 未验证：真实服务商的连接测试（本机没有 API Key）。连接测试的状态分类逻辑由单元测试（模拟 fetch）覆盖。

### 假设与决策

- **主题**：采用蓝白 / 深蓝黑，强调色都来自 logo 的蓝色；没有采用"橙黑"（原因见 `architecture.md` 的"主题"一节）。
- **服务商**：只预设公开文档明确支持 OpenAI 兼容接口的服务；连接测试只用 `GET /models`，不发送对话请求，因此不消耗 token。
- **语音**：阶段 2 只有"模拟"服务；参数先保存，麦克风和识别测试按钮显示为"即将推出"。
- **人设中的主动搭话、对话历史**：配置项先保存，标注"阶段 3 生效"；"清空对话历史"按钮禁用。
- **开机启动**：开发模式下注册的会是 `electron.exe`，因此只在打包版本中写入系统启动项，面板中会给出提示。
- **恢复默认配置**不会删除已保存的 API Key，密钥需要在 AI 配置页单独删除。

### 已知问题

- 面板一次性引入完整的 Element Plus，`settings` 脚本约 2.5 MB（未压缩）。本地加载影响不大，后续可改为按需引入。
- 开机启动未实测，要等阶段 6 打包后才能验证。
- 面板页面的交互（表单保存、主题切换）目前靠手动验收，没有组件测试。
