### 验证结果（实际执行）

- `npm test`：8 个测试文件，43 个用例全部通过。
- `npm run typecheck`、`npm run lint`、`npm run build`：通过。
- `npm run dev` 实机运行，通过注入鼠标事件并截图验证：透明背景、眼睛追踪、单击出气泡并切换表情、拖动（无误触发单击，位置写入 `config.json`）、右键原生菜单。

  - 最终 10fps + `will-change`：约占单核 8%（16 核机器总占用约 0.5%）。

- 右键菜单、托盘里未实现的入口（聊天、小游戏、设置、控制面板）显示为禁用的"（即将推出）"。
- 鼠标穿透模式下隐藏气泡，因为此时气泡无法被关闭。

### 已知问题

- Electron 44 不再通过 postinstall 下载二进制，而是在首次运行时下载；国内网络需先设置 `ELECTRON_MIRROR`（见 README）。
- npm 11 的 install-script 白名单会提示 esbuild 的 postinstall 未执行；已验证 esbuild 可以正常工作，可忽略。
- 点击桌宠会让桌宠窗口获得焦点（从当前应用夺走焦点）。阶段 3 需要在桌宠窗口内输入时再决定是否改为 `focusable: false`。
- 待机浮动在软件渲染下仍有约 8% 单核占用；可通过托盘关闭"待机动画"。后续可考虑在长时间无交互时自动降频。
- 自动化测试只覆盖纯函数；窗口行为依赖手动验收。
- 尚未在多显示器或不同 DPI 组合的环境下实测，只有单元测试覆盖可见性修正逻辑。

## 2026-10-14 · 阶段 3：AI 对话

### 完成内容

- 主进程 AI 层：`AIProvider` 接口、OpenAI 兼容实现（`/chat/completions`）、离线模拟实现（服务商"模拟（离线测试）"）；错误归类与连接测试共用。
- 提示词：由人设生成系统提示词，要求模型只返回 `{"text","emotion","speech"}` JSON；上下文最多 20 条、约 6000 字。
- 回复解析：容忍 `<think>` 块、代码块和前后多余文字；表情不在允许列表时回退为平静；不是 JSON 时按纯文本显示。
- `ChatService`：同一时间只有一个请求、可取消、超时；桌宠先显示思考，再用气泡说出回复并切换表情；出错时桌宠用难过表情说明原因。
- 对话历史：最多 200 条；开启"保存对话历史"时写入 `chat-history.json`，关闭或清空时删除。
- 主动搭话：每 60 秒检查一次，满足条件（已开启、空闲超过间隔、桌宠可见、未免打扰 / 穿透）时请求模型说一句话。
- 界面：控制面板新增"聊天"页（纯文本气泡、思考动画、停止、清空，配置不可用时给出指引）；右键菜单和托盘增加"聊天"；总览页"最近互动"显示最近的消息；人设页的"清空对话历史"可用。

### 规格调整

- 规格书建议独立的聊天输入窗口。这里放在控制面板的"聊天"页中：面板已有窗口管理、主题和安全的 IPC 边界，再开一个窗口收益不大。桌宠仍会同步显示回复。
- 暂不使用流式输出：回复要先完整解析 JSON 才能确定表情，而且回复本身很短（默认最多 512 token）。

## 2026-10-14 · 本地轻量语音（SenseVoice / Kokoro）

用户询问能否集成本地轻量化识别和合成。可以：Windows 系统语音已经是本地合成；识别没有可用的系统接口（Electron 里的 Web Speech 需要 Google 密钥），所以接入 [sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx) 的 int8 模型，在 CPU 上离线运行。

### 选型

- 识别：SenseVoice Small int8（约 228 MB），中文 / 粤语 / 英语 / 日语 / 韩语，带标点。
- 合成：Kokoro v1.1 中文 int8（约 185 MB），100 个中文音色，支持中英混读。系统语音仍然作为默认朗读（无需下载）。
- 运行时：`sherpa-onnx-node` 1.13.8，在独立的系统 Node 子进程中加载，避免推理卡住或拖垮主进程。
- 未选用 Whisper.cpp / piper：SenseVoice 对中文标点更好，Kokoro 中文音色更多；sherpa-onnx 同时覆盖识别和合成，只引入一个原生模块。

### 完成内容

- 语音设置增加"本地模型 Kokoro / SenseVoice"；底部可下载、暂停续传、导入文件夹、删除。
- 默认识别改为本地模型（未下载时会提示去下载）；默认朗读仍是系统语音。
- 模型保存在 `%APPDATA%\marimo\models\`，不进 git。

## 2026-10-14 · 本地 TTS：TTS settlement failed

Kokoro 在 Electron 44 的 `utilityProcess` 和主进程里都能加载模型，但 `generateAsync()` 以 `TTS settlement failed` 失败，同步 `generate()` 则抛 `External buffers are not allowed`。同一套模型和配置在系统 Node 中可以合成。原因是 sherpa-onnx 把样本放在 N-API external ArrayBuffer 里，Electron 44 不允许这种缓冲进入 JS。

处理：用系统 `node.exe` fork worker；样本在 Node 里拷贝并编码成 WAV，再以 base64 回传。识别仍走同一子进程，接口不变。
